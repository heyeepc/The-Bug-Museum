## 边遍历边修改列表导致的迭代器失效
错误分类：迭代器失效 (Iterator Invalidation) / 编码反模式 (Anti-Pattern)
现象描述：在用 for 循环遍历列表并试图用 .remove() 过滤掉辅音字母时，发现某些相邻的辅音字母被完美跳过，没有被删除。

假设我们有一个列表：b = ['t', 'h', 'i', 'n', 'k']。你想用 for 循环遍历它，并删除前两个辅音 't' 和 'h'。

第一次循环：
内部计数器指向索引 0，此时 b[0] 是 't'。

发现 't' 是辅音，执行 b.remove('t')。

列表发生变化：'t' 被删除了。后面的元素全部往前挪！
原本在索引 1 的 'h'，现在跑到了索引 0；原本在索引 2 的 'i'，跑到了索引 1。

此时列表变成了：['h', 'i', 'n', 'k']。

第二次循环：
内部计数器加 1，指向索引 1。

Python 去看现在的列表 b 中索引 1 的位置是谁？

此时 b[1] 已经是 'i' 了！那个 'h' 因为往前挪了一位，被完美“跳过”了！

于是 'h' 永远留在了列表中，根本没进入删除的逻辑。

这就是为什么代码在删除辅音时，总是删不干净，或者读到后面就会报错。
